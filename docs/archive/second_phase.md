Android Cloud BuildSynkro - MVP Roadmap for Cloud App Building  
First usable, real-world version.  
Goal: The smallest real version that provides actual and safe value - the user builds an Android application from within Synkro without downloading any SDK locally.  
The plan was reduced from 172 expanded tasks to only about 16 essential tasks, postponing everything that does not prevent the first launch (Mac/iOS, automatic store publishing, full billing, AI self-repair).  
A red line that must not be crossed even in the MVP: Isolation of user code execution (Sandbox) must be real from day one - a temporary, single-use, isolated Container with strict limits on time / storage / CPU / RAM. 
Other things (billing, store publishing, automatic repair) can be safely absent or simplified, but security itself cannot.  
Usage FlowThe user writes a Flutter project in Synkro.  Clicks "Build Android APK".  Project is uploaded to the build server.  An isolated container executes flutter build apk.  Live broadcast of the logs.  A direct download link for the APK is provided.  
Infrastructure & Security - Your Friend (Cloud / Infra)#AssigneeDetails1  Your Friend  Build Job Data Model: build_jobs (id, userId, projectId, status, createdAt, artifactPath) table.  2  Your Friend  Secure Build Sandbox: Temporary, single-use Docker container, automatically deleted after each build.  3  Your Friend  Resource Limits: Strict RAM / CPU / Storage limits, with a mandatory timeout.  4  Your Friend  Build Worker Service: Pulls a job from the queue, runs the sandbox, executes flutter build apk, and captures the output and logs.  5  Your Friend  Build Queue: Postgres table + simple polling without a complex queue system for the MVP.  6  Your Friend  Secure Project Upload: Project compression, uploading, and a maximum size limit.  7  Your Friend  Artifact Storage: Storing the APK, temporary download link, auto-delete after a period.  8  Your Friend  Usage Cap: Simple counter per user (e.g., 10 builds/day) following the same rate limiter pattern previously built.  Interface & Agent - You (Agent / AI)#AssigneeDetails9  You  "Build Android APK" button in the Synkro interface, initiates the process.  10  You  Upload Flow: Packaging the project and sending it via the API.  11  You  Live logs broadcast - reusing the existing Agent Terminal architecture.  12  You  Build Status (Progress UI - queued / running / success / failed).  13  You  Download Link - appears upon a successful build.  14  You  Error Display - raw log, and the agent discusses it in normal chat without a separate repair pipeline.
